# V1.1 Dify Prompt 质量优化方案

> 撰于 2026-06-13 · 基于 `dify_1.1_demo.md` 实际生成样本诊断
> 
> 目标：内容不乱不散、语气口吻与目标人群痛点共鸣强、可投产使用

---

## 零、Demo 样本诊断（7 张卡片：cover → plan → subjects → study_material ×2 → notice → cta）

### 问题 0：输入参数实际值

| 参数 | Demo 值 | 备注 |
|------|--------|------|
| exam_name | 执业医师资格证 | |
| exam_date | 2026-08-02 | |
| countdown_days | 51 | |
| target_audience | **未注入**（推测为空） | CTA 里写"姐妹"，但未体现任何人群画像 |
| theme | **未注入**（推测为空） | 全篇没有任何主题线索 |
| card_sequence | cover, plan, subjects, study_material, study_material, notice, cta | plan 只有 1 张→触发"全程备考"fallback；study_material 有 2 张→同一套器官系统重复生成 |

### 问题 1（致命）：51 天计划塞进一张卡片

plan_count=1 触发了 CODE_1 的"全程备考"fallback。一张 3:4 比例的小红书卡片塞了 51 行日期——在小程序中根本看不清，用户不会存。

**根因**：CODE_1 在 plan_count=1 时直接给了 `total_days` 天（51天）的网格，没有做视觉密度约束。

### 问题 2（严重）：两张 study_material 内容高度重复

第 4 张 → 妇产科+儿科+消化系统  
第 5 张 → 妇产科+儿科+消化系统（同一套器官系统，换个说法又来一遍）

读者感受："刚才不是看过了吗？" → 划走。

**根因**：两张 study_material 的 user_prompt 完全一样（只传了 exam_name），LLM 不知道前后文，选了相同的"最热门考点"。

### 问题 3（严重）：目标人群/主题未生效

Demo 中 `target_audience` 和 `theme` 很可能为空。CTA 写的"姐妹"是通用小红书用语，没有针对任何特定人群。封面标题是通用句式，没有人群钩子。

**根因**：V1.1 刚加了 target_audience/theme UI，但 demo 生成时这两个参数还未传入（或选择了空值）。**但即使传了**，当前 CODE_A 的 user_prompt 也没有把人群信息注入到每张卡片的生成指令中——只在 TONE_BLOCK（system_prompt）底部提了一句，LLM 很容易忽略。

### 问题 4（中等）：duration 字段被 CODE_2 覆盖

LLM 在 task 名中正确写了 `（50min）`、`（70min）` 等递增时长，但 CODE_2 合并时用了 `day.get("duration", "2h")`——把 LLM 的成果全盖成了 `"2h"`。

**根因**：CODE_2 L128-130，`duration` 取的是 days_grid 的默认值，没有从 task 名中提取 LLM 生成的时长。

### 问题 5（中等）：卡片间无叙事弧线

阅读顺序：封面(热血) → 计划(枯燥列表) → 科目(罗列) → 学习资料(长文) → 学习资料 again(长文) → 须知(清单) → CTA(互动)。

每张卡片是独立单元，读者感受不到"这篇文章在带我走完一个完整的备考认知旅程"。信息密度最高的两张 study_material 连续排列，造成阅读疲劳。

### 问题 6（轻微）：notice 卡片完全按模板填空

5 条须知中 4 条是固定模板（考试时间/必备物品/入场时间/禁止携带），只有第 5 条"考前提醒"有一点人情味。这个卡片的 prompt 太死，没有给 LLM 发挥空间。

## 一、优化总览

```
现有流程：
  START → CODE_1(参数计算) → Iterator → CODE_A(构造prompt) → LLM → CODE_2(后处理) → END

优化后流程：
  START → CODE_0(叙事规划) → CODE_1(参数计算+话题分派) → Iterator → CODE_A(构造prompt) → LLM → CODE_2(后处理+时长修复) → END
```

| 层 | 改动 | 风险 | 收益 |
|----|------|------|------|
| **CODE_0** 新增 | Iterator 前加一个 LLM 节点，生成 150 字叙事大纲 | 中（新增节点，需改 Dify 流程） | 高（解决"散"的根本手段） |
| **CODE_1** 改造 | 1. plan 密度约束 2. study_material 话题分派 3. 注入 total_cards | 低 | 高（解决计划过长、内容重复） |
| **CODE_A** 重构 | 1. TONE_BLOCK 重组 2. user_prompt 注入人群 3. 卡片差异化 4. 叙事上下文注入 | 低（只改文本） | 高（解决语气、共鸣） |
| **CODE_2** 修复 | 1. 修复 duration 覆盖 bug 2. 增强兜底 | 低 | 中（数据正确性） |

## 二、CODE_0 新增：叙事规划节点

### 2.1 Dify 配置

- **节点类型**：LLM
- **位置**：START 之后、CODE_1 之前
- **模型**：与卡片生成 LLM 相同
- **输入变量**：`exam_name`, `exam_date`, `role`, `target_audience`, `theme`, `cardSequence`（来自 START 的 cards JSON 字符串）
- **输出变量**：`narrative_plan`（string，约 150 字）

### 2.2 System Prompt

```
你是一个小红书备考内容的「主编」。你的任务不是写内容，而是为一组备考卡片制定叙事策略。

输入信息：
- 考试：{{exam_name}}
- 日期：{{exam_date}}
- 角色：{{role}}
- 目标人群：{{target_audience}}（如为空则默认"备考人群"）
- 主题方向：{{theme}}（如为空则默认"高效备考"）
- 卡片序列：{{cardSequence}}（JSON 数组，每项含 type 字段）

你需要输出一个叙事大纲（不超过 150 字），包含：

1.【整体基调】（一句话定义整组卡片的情绪基调）
   - 在职备考 → 务实、高效、理解你的累
   - 宝妈备考 → 温柔、共情、带娃也能上岸
   - 零基础 → 鼓励、清晰、从入门到精通
   - 非科班 → 策略、方法、"跨专业不是劣势"

2.【每张卡片的核心信息】（每张卡片一句话，不超过 15 字）
   - cover：必须体现人群钩子，不是通用标题
   - plan：阶段感、每日时长趋势
   - subjects：按性价比的差异化策略
   - study_material：每张卡片各自覆盖不重复的知识模块
   - notice：不止是清单，要带人情味
   - cta：针对人群的真实痛点提问

3.【卡片间过渡】用 1-2 句话描述卡片之间的逻辑关系
   - 例如："封面承诺三阶段计划 → 计划证明这不是空话 → 科目告诉你怎么分配时间..."

输出格式（严格纯文本，不要 Markdown）：
整体基调：...
封面核心信息：...
计划核心信息：...
科目核心信息：...
（按实际卡片顺序每张一行）
过渡逻辑：...
```

### 2.3 User Prompt

```
请根据以上输入为以下卡片序列制定叙事大纲：
{{cardSequence}}

确保每张卡片的核心信息互不重复，形成从"认知唤醒→计划→知识→工具→行动"的完整阅读旅程。
```

### 2.4 输出注入路径

CODE_0 的输出 `narrative_plan` 传给 CODE_1，再由 CODE_1 注入到每张 enriched_card 的 `narrative_plan` 字段，最终 CODE_A 将其追加到每张卡片的 system_prompt 开头。

### 3.2 study_material 话题分派：避免同一主题重复

```python
# 在 CODE_1 的 enriched 循环中，为 study_material 卡片分配不重叠的话题域

# 预定义执业医师的话题域（按考试科目划分）
STUDY_TOPIC_DOMAINS = [
    "呼吸系统+循环系统",
    "消化系统+泌尿系统",
    "妇产科+儿科",
    "神经精神+运动系统",
    "内分泌+血液系统",
    "传染病+免疫+药理",
]

# 收集所有 study_material 卡片的索引
sm_indices = [i for i, c in enumerate(cards) if c.get("type") == "study_material"]
sm_count = len(sm_indices)

# 为每张 study_material 卡片分配不同的话题域
for sm_idx_pos, card_idx in enumerate(sm_indices):
    # 轮询分配，如果卡片数量超过话题域数量则取模
    domain = STUDY_TOPIC_DOMAINS[sm_idx_pos % len(STUDY_TOPIC_DOMAINS)]
    enriched[card_idx]["study_topic_domain"] = domain
```

### 3.3 注入叙事上下文 + 卡片位置

# 在 enriched 循环中，为每张卡片追加

## 四、CODE_A 重构（核心改动）

### 4.1 TONE_BLOCK 重组：人群适配提前，加硬约束

当前结构：
```
[角色人设] → [口吻风格] → [内容偏好] → [目标受众适配] → [主题方向] → [通用规则]
```

优化后结构：
```
[叙事大纲（来自主编）]        ← ★ 新增，放最前面
[目标受众 — 必须定制每句话]   ← ★ 提前，加自检指令
[主题方向]                    ← ★ 提前
[角色人设]                    ← 保留
[口吻风格 + 口头禅 + 禁用词]   ← 保留
[通用写作规则]                ← 合并精简
```

**关键改动**：受众段增加"自检指令"

```python
AUDIENCE_BLOCK = (
    "【★ 目标受众 — 你必须为这个人群定制每一句话】\n"
    + "你的读者是：" + target_audience + "\n\n"
    + audience_profile["persona"] + "\n"
    + audience_profile["emphasis"] + "\n\n"
    + "★ 自检规则（生成每条内容后必须自问）：\n"
    + '"一个' + target_audience + '的人看到这条，会觉得在说自己吗？"\n'
    + "如果不会 → 重写。如果会 → 保留。\n\n"
    + audience_profile["examples"] + "\n"
    + audience_profile["phrases"] + "\n\n"
)
```

### 4.2 plan 卡片 prompt 优化：处理单张超长计划

当 plan_count=1 且天数 > 30 时：

```
你现在的任务：「{exam_name}」考试的全程备考计划。

⚠️ 这张卡片只有 1 张，但备考天数超过 30 天。你不能逐日列出——在小红书 3:4 卡片上 50 行文字根本没人看。

★ 采用「三阶段摘要 + 每周代表日」结构：

1. 把 {phase_days} 天拆成 3 个阶段，每个阶段写 1 行摘要（包含起止日期、阶段目标、每日时长）
2. 每个阶段选 2-3 个代表日展示（标注日期 + 任务名 + 时长）
3. 每阶段末尾标注工具建议
4. 确保有 2-3 个复盘日穿插其中

输出格式：
title: 「{phase_name}」（简短有力，10字以内）
subtitle: 三阶段摘要，用「·」连接

cards 的 days 数组只输出 15-20 个代表日（从完整日期网格中均匀采样，但复盘日和休息日必须保留）。
```

### 4.3 subjects vs priority 互斥差异化

**subjects prompt 追加**：
```
⚠️ 与「备考优先级」卡片的区别：
- 你是「各科考什么、怎么学」——侧重学习方法和内容概述
- priority 卡片是「各科值多少分、先学哪个」——侧重分值和顺序

**priority prompt 追加**：
```
⚠️ 与「考试科目」卡片的区别：
- 你是「各科值多少分、先学哪个」——侧重分值和性价比排序
- subjects 卡片是「各科考什么、怎么学」——侧重学习方法
- 你的 label 必须包含分值信号（"约XX分""占比最高""分值大头"）
- 你的 content 只写为什么值得/不值得花时间，不写具体学习方法
```

### 5.1 修复 duration 被覆盖（核心 bug）

# L128-130 原代码：
merged_days.append({

# 修复后：
# 从 LLM 生成的 task 名中提取时长（如 "生理学·细胞功能（50min）" → "50min"）
import re
def extract_duration(task_name, default_duration):
    """从 task 名中提取 LLM 生成的时长，提取不到则用默认值"""
    match = re.search(r'[（(](\d+min)[）)]', task_name)
    if match:
        return match.group(1)
    match = re.search(r'[（(](\d+\.?\d*h)[）)]', task_name)
    if match:
        return match.group(1)
    return default_duration

merged_days.append({
    "date": day.get("date", ""),
    "weekday": day.get("weekday", ""),
    "task": task_name,
    "duration": ("休息" if is_rest else extract_duration(task_name, day.get("duration", "2h"))),
})
```

## 九、待讨论项

1. **CODE_0 的 LLM 调用会增加延迟**：多一次 LLM 调用（约 1-3 秒），总生成时间从 ~15s 增加到 ~18s。是否可接受？
   - 替代方案：CODE_0 不用 LLM 而用 CODE（规则引擎），速度更快但灵活性差。建议先用 LLM 节点跑通，后续如果延迟不可接受再优化为规则引擎。

2. **话题域列表的通用性**：`STUDY_TOPIC_DOMAINS` 目前只覆盖医师考试。对于护士/教资/注安/消防，需要各自的话题域列表。方案：
   - 在 CODE_1 中根据 exam_name 匹配话题域（当前先 hardcode 医师的，后续扩展到其他考试）
   - 或者把话题域作为一个配置变量从 START 传入

3. **A/B 测试建议**：如果条件允许，建议保留当前 Workflow 作为 baseline，新建一个优化版 Workflow。通过前端 feature flag 控制 10% 流量走新版，对比收藏率/互动率后再全量切换。
