# V3 工作流优化大纲 — 数据库驱动的内容生产

> 状态：待评审  
> 目标：让 LLM 产出的文章更稳定、更权威、更像"考过的人写的"

---

## 一、现状分析

### 1.1 当前数据流

```
START(cert_id, topic, audience)
  → ② CODE_fetch_materials  ─── 查 policy_fact 政策事实 + 爆款样本
    → ③ LLM 标题              ─── 注入 brief_json + viral samples
      → ④ LLM 正文            ─── 注入 brief_json + viral samples + 选定标题
        → ⑤ LLM 封面+标签     ─── 拿到正文生成封面
          → ⑥ CODE_fact_check ─── 正则比对正文 vs policy_json
            → END
```

### 1.2 核心问题

| 问题 | 表现 | 根因 |
|------|------|------|
| 文章空洞 | "制定合理计划，坚持每天刷题" | 缺少真实考点锚点，LLM 只能写通用鸡汤 |
| 引用模糊 | "根据相关规定" | 没传条文原文，LLM 只能含糊带过 |
| 事实不可靠 | 编造不存在的知识点 | 事实校验只做日期/数字正则，不管知识准确性 |
| V2 知识库未接通 | study_material 卡片用 LLM 记忆 | knowledge_point 表有数据但没人查 |

## 三、分场景优化方案

### 3.1 V3 文章生产流水线

#### P0 — 知识注入（节点 ② + ④）

**目标**：文章能具体到"循环系统占 80 分、COPD 每年必考"这种颗粒度。

**改动**：

```
policy_api.py
  └── 新增 POST /query/knowledge     ← 查 exam_subject + knowledge_point + exam_question

CODE_fetch_materials.py
  └── main() 新增调用 /query/knowledge
  └── build_brief() 注入知识点到 brief_json
```

**效果对比**：

```
改前 brief_json:
  证书：执业医师（执业医师）
  报考条件：本科·本专业·试用满1年...
  最新考试时间：2025-06-14

改后 brief_json:
  证书：执业医师（执业医师）
  报考条件：本科·本专业·试用满1年...
  最新考试时间：2025-06-14

  【高频考点】（来自知识库，请在正文中至少覆盖 3 个）
  - 心血管系统（约80分）：心力衰竭诊断标准、冠心病分型、高血压分级
    真题考法：病例分析题为主，给症状+检查结果→判断病变
  - 呼吸系统（约45分）：COPD诊断（FEV1/FVC＜0.7）、哮喘分级治疗
  ...
```

#### P1 — 权威引用（节点 ② + ④）

**目标**：把"根据相关规定"变成"根据《医师法》第九条"。

**改动**：

```
CODE_fetch_materials.py
  └── build_brief() 中嵌入 policy_doc.doc_title + policy_clause.clause_section

LLM System Prompt（节点 ④）
  └── 增加约束："每个政策性结论后面必须标注文件名+条款号"
```

**效果**：

```
改前：取得执业助理医师资格后，需要工作满一定年限才能报考执业医师。
改后：根据《中华人民共和国医师法》第九条第二项，取得执业助理医师资格后，
      执业满 2 年（大专）或 5 年（中专）方可报考执业医师。
```

#### P2 — 事实校验升级（节点 ⑥）

**目标**：不只校验日期数字，还要校验知识点是否真实存在。

**两种方案**：

| 方案 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| A. 服务端校验 | 调用 `/query/fact_check`（已有接口，可扩展） | 快，不耗 token | 只能做存在性检查 |
| B. LLM 逐句核对 | 把 knowledge_json 注入 Code 节点，LLM 逐句比对 | 能判断语义准确性 | 慢，耗 token |

**建议**：先用 A 做存在性检查（正文中提到的疾病名/药名/数值，DB 里有没有），发现可疑再人工复核。

### 3.2 V2 卡片生成流水线

#### P2 — study_material 接通知识库

**现状**：`CODE_A.py` 中 `study_material` 卡片有 `knowledge_base` 模式，当 `assigned_chapter` 非空时生效，但数据来源是 Weaviate 向量检索，未接入 policy_fact 的结构化数据。

**改动**：

```
workflow 调整（不改 CODE_A 架构）：
  在 Iterator 之前插入一个 Code 节点：
    cert_id → 查 knowledge_point（按 subject 分组） → 分发给每张 study_material 卡片

  CODE_A.py 的 study_material 分支：
    已有 knowledge_base 模式的 System Prompt，只需数据源从 Weaviate 换成 policy_fact
```

#### P3 — subjects / priority / mnemonics 数据驱动

| 卡片 | 改造 |
|------|------|
| subjects | `exam_subject` 提供真实科目名，不再靠 LLM 记忆 |
| priority | `exam_question` 按科目统计数量 → 反推分值分布 |
| mnemonics | `knowledge_point` 的考点名作为口诀锚点，减少编造 |
