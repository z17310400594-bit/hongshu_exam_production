# 角色卡片体系设计

## 版本
v1 — 2026-06-27

## 状态
设计文档，非实现计划。整理三角色内容哲学的差异，明确当前瓶颈和长期方向。

---

## 一、问题的本质

当前 9 种卡片类型是为**内容号**设计的骨骼：

```
内容号 = 过来人分享 → 内容是「经验」
卡片骨架：封面 → 计划 → 科目 → 考点 → 考前须知 → 行动引导
```

陪考号和分析号不是内容号的变体——它们是不同的内容品类，需要不同的骨骼。

### 1.1 三角色的内容哲学

| 维度 | 内容号 | 陪考号 | 分析号 |
|------|--------|--------|--------|
| 身份 | 考过的过来人 | 帮人做计划的教练 | 读政策拆数据的人 |
| 内容产品 | 备考经验 | 决策替代 | 信息差 |
| 免费内容的价值 | 「有人踩过坑，你可以少走」 | 「有人替你做了决定，你照做」 | 「有人读了文件，告诉你结论」 |
| 付费产品 | 完整资料包 / 课程 | **9.9 冲刺计划**（每日任务清单） | **完整分值分布报告** |
| 用户为什么付费 | 想节省整理时间 | 想省掉决策精力 | 想知道该重点学什么 |
| 信任建立方式 | 真诚分享、暴露错误 | 判断准确、方案有效 | 数据扎实、结论可查 |

### 1.2 为什么"换透镜不够"

当前做法：同一张 plan 卡，内容号写"我当时在基础阶段…"，陪考号写"为什么这样排…"。问题是：

- **陪考号的 plan 应该是产品，不是免费内容。** 免费内容露出片段 → 完整版付费。但现在的卡片体系把 plan 当免费内容分发——3 张 plan 卡几乎等于把计划全给了，C2A 再推"完整计划"已经没有说服力。
- **分析号不需要 study_material。** 分析号不讲考点——讲考点是内容号的活。分析号的内容是「数据判断」：这个考点值不值得花时间、这个科目分值在涨还是在跌。

"透镜"能让同一张卡写得像不同角色，但**不能改变卡片类型本身承载的内容品类**。

## 二、现有 9 种卡的角色适配分析

| 卡片 | 内容号 | 陪考号 | 分析号 | 判断 |
|------|--------|--------|--------|------|
| **cover** | ✓ 经历共鸣钩子 | ✓ 变体：决策钩子（"X天，只做Y件事"） | ✓ 变体：数据钩子（"近3年分值数据跑完了"） | 三角色通用，变体即可 |
| **plan** | ✓ 核心内容 | **✗ 这是产品不是内容** | ✗ 分析号不排计划 | 内容号专属。陪考号的计划是付费产品 |
| **subjects** | ✓ 过来人排序 | ✗ 太学术，教练不讲科目概述 | ？变体：按分值排序，带数据信号 | 可复用但不理想 |
| **priority** | ✓ 经验判断 | ✗ 教练不讲分值，讲"先啃哪个" | ✓ 核心内容 | 分析号核心 |
| **study_material** | ✓ 核心内容 | ？变体：不讲"我当时"，讲"考什么→怎么拿分→记住这个" | ✗ 不讲考点 | 内容号专属。陪考号需要变体 |
| **notice** | ✓ 过来人 checklist | ✗ 太通用，打断教练叙事 | ？变体：规则解读（引用文件依据） | 对陪考号是噪音 |
| **resources** | ✓ 过来人推荐 | ✗ 教练不推资料 | ✗ 不做资料推荐 | 内容号专属 |
| **mnemonics** | ✓ 个人化口诀 | ？变体：短口诀，不讲编的过程 | ✗ 太"技巧型" | 可复用但不理想 |
| **cta** | ✓ 互动引导 | **✓ 产品入口（当前未生效）** | ✓ 报告入口 | 三角色通用，内容完全不同 |

**结论**：9 种卡里，只有 cover 和 cta 是三角色通用的。其余 7 种都是内容号专属或需要大改。

## 三、陪考号：应该是什么卡片

### 3.1 内容哲学

陪考号不是「陪着你考」——是**「替你决策」**。

- 用户不需要知道「为什么这样排」——那是内部逻辑
- 用户需要的是「今天干什么」「这个考点怎么拿下」「还有多少没搞完」
- 免费内容给**片段**——让人感觉「有个人替我想好了」
- 付费产品是**完整计划**——「精确到每天+真题配哪道+考前最后一天动作级清单」

### 3.2 建议卡片类型

```
封面（决策钩子）
  → 每日任务卡：「今天只磕共犯形态，60分钟够了」
  → 聚焦卡：「正当防卫每年必出一道——就记5个条件」
  → 避坑卡：「这块80%的人第一遍会错，你先看这个」
  → 进度卡：「刑法还剩3块，按这个节奏刚好」
  → 复盘卡：「这周最容易忘的3个点，周末过一遍」
  → CTA（产品入口）：「完整34天计划+每日任务清单，跟吗」
```

### 3.3 新卡片类型定义

#### daily_mission（每日任务）
- **核心**：今天只做这一件事。标题是任务名，内容是「怎么做」。
- **与 plan 的区别**：plan 是日历（哪天干嘛），daily_mission 是单日任务指令。
- **免费版**：给 1-2 天样本。完整版在付费产品里。

#### focus_point（聚焦卡）
- **核心**：一个考点，用最少的话讲清楚「考什么 + 怎么拿分 + 记住什么」。
- **与 study_material 的区别**：study_material 讲「考点详解+记忆方法」，focus_point 讲「就记这个条件，题直接秒」。
- **长度**：3-5 行，不是 3-5 段。

#### trap_warning（避坑卡）
- **核心**：一个高频易错点，告诉读者「别人都栽在这，你别栽」。
- **语气**：不是分享个人经历，是预测你会错。「这道题的坑在第二步——80%的人选了B其实选D」。

#### progress_check（进度卡）
- **核心**：「你已经搞完了X，还剩Y，按这个节奏Z天能搞定」。
- **价值**：给人掌控感——不是自己在黑暗中摸索，是有人替你算好了。

#### review_flash（复盘卡）
- **核心**：阶段性的「最容易忘的几个点，周末过一遍」。
- **价值**：降低遗忘焦虑——不是让你全复习，就这几个。

## 四、分析号：应该是什么卡片

### 4.1 内容哲学

分析号不是「分析考试」——是**「替你读文件、跑数据」**。

- 用户不知道近 3 年分值变化——你告诉他
- 用户不知道今年大纲改了哪里——你标出来
- 用户不知道该把时间花在哪——你按数据排序
- 免费内容给**片段数据**——让人感觉「这人读得真细」
- 付费产品是**完整报告**——「分值分布+高频考点清单+政策变动解读」

### 4.2 建议卡片类型

```
封面（数据钩子）
  → 分值分布卡：「民法合同编连续3年分值第一，今年大概率保持」
  → 趋势预警卡：「行政法今年大纲变了3处，2处必考」
  → 避坑卡：「法制史年均3分但背诵量排前3——数据不支持花时间」
  → 科目效率排序：「按分值/时间投入比排的优先级，不是课本顺序」
  → 政策解读卡：「新修的XX法对考试的影响——只影响了这2个考点」
  → CTA（报告入口）：「完整分值分布报告+高频考点清单已出」
```

### 4.3 新卡片类型定义

#### score_breakdown（分值分布卡）
- **核心**：一张卡讲一个数据发现。比如「民法合同编近3年分值：21→24→28」。
- **与 priority 的区别**：priority 是排序列表（6科排排坐），score_breakdown 是一个数据点的深度解读（为什么涨、意味着什么）。
- **数据必须有来源**：年份、卷别、题型。

#### trend_alert（趋势预警）
- **核心**：「XX变了」。大纲变动、分值趋势、出题规律变化。
- **必须有数据对比**：去年 vs 今年，前年 vs 去年。
- **必须给判断**：变了之后对备考意味着什么——不是报新闻，是给判断。

#### policy_diff（政策解读卡）
- **核心**：一份文件/一条新规，拆成「对考试的影响」。
- **不说「可能」「我觉得」**——说「从数据来看」「近X年试卷显示」。

#### trap_by_data（数据避坑卡）
- **核心**：用数据纠正一个常见误区。「你以为法制史很重要——近3年年均3分，而刑法共犯形态年均12分」。
- **与陪考号 trap_warning 的区别**：陪考号讲的是做题陷阱，分析号讲的是认知偏差（对考试的误判）。

## 五、短期 vs 长期

### 短期（当前 v4/v5 阶段）

在现有 9 种卡片框架内，用角色透镜最大化差异：

| 角色 | 卡片序列 | 核心改动 |
|------|---------|---------|
| 内容号 | cover → plan → plan → subjects → study_material → notice → cta | 不变 |
| 陪考号 | cover → plan → plan → plan → study_material → study_material → cta | plan 写成"为什么这样排"，study_material 写成"武器化考点"，CTA 是产品入口 |
| 分析号 | cover → priority → subjects → study_material → study_material → notice → cta | priority 是第一张内容卡，study_material 带数据信号，CTA 是报告入口 |

**权宜之处**：
- 陪考号的 plan 卡仍然是免费内容（但改成 3 张，露出更少每天信息，更像"展示计划逻辑"而非"给你完整计划"）
- 分析号的 study_material 仍然讲考点（但带数据：近X年考了Y次）

### 长期（v6+，新卡片类型）

1. **CODE_A + 前端同时支持新卡片类型**
2. **陪考号专属**：daily_mission, focus_point, trap_warning, progress_check
3. **分析号专属**：score_breakdown, trend_alert, policy_diff, trap_by_data
4. **前端**：每个新卡类型有对应的渲染组件
5. **旧卡类型**：内容号继续用现有 9 种，不删

## 六、当前优先级

| 优先级 | 事项 | 理由 |
|--------|------|------|
| P0 | CTA 透镜生效 | 陪考号 CTA 写成了内容号——这是 bug |

| P2 | 设计陪考号新卡类型详细 spec | 需要先验证短期方案效果 |

| P3 | 新卡类型实现 | 需要前端 + CODE_A + CODE_1 联动 |

## 七、开放问题

1. **陪考号的 plan 卡到底要几张？** 3 张免费 plan 几乎等于把计划全露了。要不要缩到 1-2 张，每张只给 3-4 天？
2. **分析号的 study_material 变形到什么程度？** 当前"透镜版"study_material 加数据信号（近X年考了Y次），但本质上还是在讲考点。分析号要不要彻底不讲考点，只讲数据？
3. **新卡类型在 Dify workflow 里怎么加？** CODE_A 要加新分支。前端 Canva 渲染要加新组件。这需要至少 2-3 天的开发周期——什么时候启动？
4. **CODE_1 的卡片分派逻辑要不要改？** 当前 CODE_1 不管卡片类型，只做数据注入。如果分析号不需要某些数据（如 phase 计算），是不是该让 CODE_1 也角色感知？
