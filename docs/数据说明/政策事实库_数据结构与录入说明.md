# 政策事实库 — 数据结构与录入说明

> 共享库：客服售前咨询 + 小红书内容生产 都用这一份。
> 设计原则：事实结构化 + 原文可溯源 + AI 只检索引用不生成政策。

## 连接信息
- 库：`policy_fact`（容器 `policy-db`，宿主机 `localhost:5433`）
- 用户/密码：`policy` / `policy123`
- 导入命令：`docker exec -i policy-db psql -U policy -d policy_fact < 文件.sql`

---

## 一、表清单与关联关系

共 10 张表，核心是「**政策原文 → 条款 → 结构化事实**」溯源链：

```
cert_basic（证书）
  ├─ exam_subject          科目+合格线
  ├─ exam_condition        报考条件（最核心）──┐
  ├─ years_calc_rule       年限计算规则        │ source_clause_id
  ├─ exemption             免考条件            │ （指向 policy_clause）
  ├─ exam_schedule         考试时间            │
  ├─ score_management      成绩管理            │
  └─ registration_policy   注册继续教育        │
                                            │
policy_doc（政策原文）── policy_clause（条款）─┘
```

**关键关联**：每条结构化事实（exam_condition / exemption 等）都有 `source_clause_id` 字段指向 `policy_clause.clause_id`，条款再指向 `policy_doc.doc_id`。这样回答用户时能给出"依据：xx号文件第X条"。
> 注意：`source_clause_id` 不加外键约束（避免循环依赖），靠应用层保证一致。

---

## 二、录入顺序（重要，有依赖）

```
1. cert_basic          必须先有证书，其他表都挂它
2. policy_doc          录政策原文（溯源的根）
3. policy_clause       录条款（依赖 policy_doc）
4. exam_subject        科目（依赖 cert_basic）
5. years_calc_rule     年限规则（依赖 cert_basic）
6. exam_condition      报考条件（关联 clause，挂 source_clause_id）
7. exemption           免考（关联 clause）
8. exam_schedule       考试时间
9. score_management    成绩管理
10. registration_policy 注册继续教育
```

## 三、逐表字段说明与示例

### 1. `cert_basic` 证书主表
| 字段 | 说明 | 示例 |
|------|------|------|
| cert_id | 证书ID（主键，自定规则） | `yj_jzs` |
| cert_name | 全称 | 一级建造师 |
| short_name | 简称 | 一建 |
| cert_code | 资格目录代码 | （可空） |
| issuing_authority | 颁发部门 | 住房和城乡建设部 |
| exam_authority | 考试组织 | 人社部+住建部 |
| profession_category | 准入类/水平评价类 | 准入类 |
| valid_nationwide | 全国有效 | true |

### 2. `policy_doc` 政策原文表
| 字段 | 说明 | 录入要点 |
|------|------|---------|
| doc_id | 文件ID（主键） | 自定义，如 `doc_yj_jzs_2017` |
| doc_title | 文件标题 | 全称 |
| issuing_authority | 发文机关 | 人社部、住建部 |
| doc_number | 文号 | `人社部规〔2017〕12号` |
| publish_date / effective_date | 发布/生效日期 | DATE 格式 `2017-05-15` |
| effective_status | 现行/修订/废止 | **必须维护**，过期政策改废止但不删 |
| source_url | 官方链接 | 备查 |
| raw_text | 全文正文 | 粘贴整篇政策文本 |

### 3. `policy_clause` 条款表（事实↔原文桥接）
| 字段 | 说明 |
|------|------|
| clause_id | 条款ID（主键） |
| doc_id | 所属文件（FK→policy_doc） |
| clause_section | 条款定位，如 `第二条第二款` |
| clause_text | 条款原文 |
| clause_summary | 一句话摘要（可AI生成） |
| relates_to_type | 关联事实类型：condition/subject/exemption… |
| relates_to_id | 关联的事实ID（如 cond_001） |

> 录入时先录 policy_doc，再把它拆成条款录入 policy_clause。

### 4. `exam_subject` 科目表
| 字段 | 说明 | 示例 |
|------|------|------|
| subject_id | 科目ID（主键） | `yj_jzs_fagui` |
| cert_id | 所属证书 | `yj_jzs` |
| subject_name | 科目名 | 建设工程法规及相关知识 |
| full_mark / pass_mark | 满分/合格分 | 130 / 78（**必须字段化**） |
| exam_duration | 时长 | 3小时 |
| question_types | 题型 | 单选70+多选30 |

### 5. `exam_condition` 报考条件表（最核心）
| 字段 | 说明 | 示例 |
|------|------|------|
| condition_id | 主键 | `cond_001` |
| cert_id | 证书 | `yj_jzs` |
| degree_level | 大专/本科/硕士/博士（CHECK约束） | 本科 |
| major_category | 本专业/相关专业/其他专业/不限 | 本专业 |
| work_years_construction | 施工管理工作年限要求 | 3 |
| total_work_years | 总工作年限要求 | 4 |
| years_calc_rule_id | 关联年限规则 | `rule_001` |
| note | 备注/例外（二期建专门表前先用它扛） | |
| source_clause_id | 溯源条款 | `clause_002` |

> 按"学历×专业×年限"组合建行，每种组合一行。用户问"我能不能考"直接查这张表。

### 6. `years_calc_rule` 年限计算规则表
| 字段 | 说明 |
|------|------|
| rule_id | 主键 |
| cert_id | 证书 |
| education_type | 全日制/成人教育/自考/网络教育 |
| calc_method | 毕业起算/入学起算/累计 |
| exclude_period | 不计入的时间段，如"全日制在校学习时间不计入" |
| applicable_condition | 适用条件 |
| source_clause_id | 溯源 |

> 年限纠纷是考证头号客诉，必须结构化。

### 7. `exemption` 免考条件表
| 字段 | 说明 |
|------|------|
| exemption_id | 主键 |
| cert_id | 证书 |
| condition_description | 免考条件描述，如"已取得一级项目经理资质证书" |
| exempt_subjects | 免考科目 |
| remaining_subjects | 仍需考科目 |
| source_clause_id | 溯源 |

### 8. `exam_schedule` 考试时间表
| 字段 | 说明 |
|------|------|
| schedule_id | 主键 |
| cert_id | 证书 |
| year | 年份（INT） |
| registration_start / registration_end | 报名起止（DATE） |
| exam_date | 考试日期 |
| result_date | 成绩公布 |
| region_note | 各省差异说明 |

> 每年更新一行，历史保留（要能答"去年什么时候考"）。

### 9. `score_management` 成绩管理表
| 字段 | 说明 |
|------|------|
| cert_id | 主键=证书 |
| rolling_period | 滚动周期，如 `2年` |
| rule_description | 滚动规则说明 |
| source_clause_id | 溯源 |

### 10. `registration_policy` 注册与继续教育表
| 字段 | 说明 |
|------|------|
| cert_id | 主键=证书 |
| initial_reg_period | 初始注册有效期 |
| renewal_period | 延续注册周期 |
| ce_hours | 继续教育学时 |
| ce_note | 说明 |
| source_clause_id | 溯源 |

## 四、录入方式

### 方式 A：SQL（少量数据）
照 `政策事实库_种子数据样例与导入说明.sql` 格式写 INSERT，存 .sql 文件执行。

### 方式 B：CSV 批量导入（大量数据，推荐）
每张表一个 CSV，首行列名。导入命令（以 exam_condition 为例）：
```bash
docker exec -i policy-db psql -U policy -d policy_fact -c \
"\copy exam_condition(condition_id,cert_id,degree_level,major_category,work_years_construction,total_work_years,source_clause_id) \
FROM '/dev/stdin' WITH (FORMAT csv, HEADER true)" < exam_condition.csv
```
> CSV 必须 UTF-8 编码。

### 方式 C：DBeaver 图形工具
下载 DBeaver → 新建 PostgreSQL 连接 `localhost:5433 / policy_fact / policy / policy123` → 表上右键"导入数据"选 CSV。

## 五、录入后必跑校验

```sql
-- 1. 报考条件漏挂条款（source_clause_id 为空）
SELECT condition_id, cert_id FROM exam_condition WHERE source_clause_id IS NULL;

-- 2. 孤儿条款（指向不存在的原文）
SELECT c.clause_id FROM policy_clause c
LEFT JOIN policy_doc d ON c.doc_id=d.doc_id WHERE d.doc_id IS NULL;

-- 3. 引用了废止政策（合规检查）
SELECT c.clause_id, d.effective_status FROM policy_clause c
JOIN policy_doc d ON c.doc_id=d.doc_id WHERE d.effective_status='废止';
```

## 六、避坑

1. **政策库人工核对入库**——别让 AI 写政策，AI 只检索引用
2. **数字字段（年限/合格线/日期）必须结构化**——不能塞文本让 AI 猜
3. **`effective_status` 必须维护**——不标记失效，AI 会拿废止文件回答
4. **条款溯源不能省**——考证用户极度关注"依据是什么"
5. **年限计算规则单独建表**——全日制扣除是高频纠纷点
