# 真题库 — 数据结构与录入说明

> 共享库：客服答考点问题 + 小红书干货文引用真题 都用这一份。
> 依赖：本库引用政策事实库的 `cert_basic`（证书）和 `exam_subject`（科目），录真题前确保证书和科目已存在。

## 连接信息
- 库：`policy_fact`（容器 `policy-db`，宿主机 `localhost:5433`）
- 用户/密码：`policy` / `policy123`
- 导入命令：`docker exec -i policy-db psql -U policy -d policy_fact < 文件.sql`

---

## 一、表清单与关联关系

共 3 张表，核心是「**题目 ↔ 考点**」多对多：

```
cert_basic（证书，政策库）──┐
exam_subject（科目，政策库）─┤
                          │
knowledge_point（考点）─────┤  kp_id
                          │   │
exam_question（真题）──────┘   │  question_id
                          │   │
exam_question_kp（关联）── question_id + kp_id（多对多）
```

- `knowledge_point` 挂证书 + 科目（科目可空=跨科目通用考点）
- `exam_question` 挂证书 + 科目 + 年份 + 题型
- `exam_question_kp` 把题目和考点多对多关联（一道题可考多个考点，一个考点有多道题）

**为什么要关联**：
- 客服答"xx考点怎么考"→ 反查该考点的真题
- 统计考点频次（被多少真题考过）→ 标记高频/低频
- 小红书干货文 → 取高频考点 + 引用真题

---

## 二、录入顺序（有依赖）

```
0. （前置）政策库里 cert_basic、exam_subject 已存在
1. knowledge_point    先录考点
2. exam_question      再录真题
3. exam_question_kp   最后建题目↔考点关联
```

## 三、逐表字段说明与示例

### 1. `knowledge_point` 考点表
| 字段 | 说明 | 示例 |
|------|------|------|
| kp_id | 考点ID（主键） | `kp_001` |
| cert_id | 证书（FK→cert_basic） | `yj_jzs` |
| subject_id | 科目（FK→exam_subject，可空=通用） | `yj_jzs_fagui` |
| kp_name | 考点名称 | 投标文件编制要求 |
| kp_chapter | 章节 | 第三章 建设工程发承包法律制度 |
| frequency | 高频/中频/低频（CHECK） | 高频 |
| note | 备注 | |

> 频次可先按经验填，后期根据 exam_question_kp 统计的实际命中数修正。

### 2. `exam_question` 真题表
| 字段 | 说明 | 示例 |
|------|------|------|
| question_id | 题目ID（主键） | `q_001` |
| cert_id | 证书 | `yj_jzs` |
| subject_id | 科目 | `yj_jzs_fagui` |
| exam_year | 真题年份（INT） | 2023 |
| question_type | 单选/多选/案例/判断（CHECK） | 单选 |
| content | 题干（TEXT） | 根据《招标投标法》…… |
| options | 选项（JSONB） | `{"A":"...","B":"..."}` |
| answer | 正确答案 | `A` 或 `ABD` |
| analysis | 解析（TEXT） | 《招标投标法》规定…… |
| difficulty | 难度 1-5（SMALLINT） | 2 |

**options 字段怎么存**：JSONB 格式，键是选项号，值是选项文本：
```json
{"A":"投标人应当具备承担招标项目的能力","B":"投标人可以低于成本的报价竞标","C":"...","D":"..."}
```
> 案例题没有客观选项时，options 填 null，把材料/问题写进 content，答案写进 answer。

### 3. `exam_question_kp` 题目↔考点关联表
| 字段 | 说明 |
|------|------|
| question_id | 题目（FK→exam_question，删题级联） |
| kp_id | 考点（FK→knowledge_point，删考点级联） |
| | 联合主键 (question_id, kp_id) |

> 一道题关联多个考点就插多行。删题或删考点时关联自动清除（ON DELETE CASCADE）。

## 四、录入示例（SQL）

```sql
-- 考点
INSERT INTO knowledge_point (kp_id, cert_id, subject_id, kp_name, kp_chapter, frequency) VALUES
 ('kp_001','yj_jzs','yj_jzs_fagui','投标文件编制要求','第三章 建设工程发承包法律制度','高频');

-- 真题
INSERT INTO exam_question (question_id, cert_id, subject_id, exam_year, question_type, content, options, answer, analysis, difficulty) VALUES
 ('q_001','yj_jzs','yj_jzs_fagui',2023,'单选',
  '根据《招标投标法》，下列关于投标人的说法正确的是：',
  '{"A":"投标人应当具备承担招标项目的能力","B":"投标人可以低于成本的报价竞标","C":"可以以他人名义投标","D":"可以相互串通投标报价"}',
  'A',
  '《招标投标法》规定投标人应当具备承担招标项目的能力；不得低于成本报价，不得以他人名义投标或串通。故A正确。',
  2);

-- 关联（这道题考了 kp_001 这个考点）
INSERT INTO exam_question_kp (question_id, kp_id) VALUES
 ('q_001','kp_001');
```

## 五、录入方式

### 方式 A：SQL（少量）
照上面格式写 INSERT，存 .sql 执行。

### 方式 B：CSV 批量（大量真题，推荐）
真题量大，CSV 最合适。注意 options 字段是 JSONB，CSV 里直接写 JSON 字符串：
```
question_id,cert_id,subject_id,exam_year,question_type,content,options,answer,analysis,difficulty
q_002,yj_jzs,yj_jzs_fagui,2022,多选,下列属于安全生产责任制内容的有：,"{""A"":""主要负责人全面负责"",""B"":""项目负责人负责"",""C"":""专职安全员日常检查"",""D"":""作业人员无需了解危险因素""}",ABC,主要负责人/项目负责人/专职安全员各负其责；D错误,3
```
导入：
```bash
docker exec -i policy-db psql -U policy -d policy_fact -c \
"\copy exam_question(question_id,cert_id,subject_id,exam_year,question_type,content,options,answer,analysis,difficulty) \
FROM '/dev/stdin' WITH (FORMAT csv, HEADER true)" < exam_question.csv
```
> CSV 里 JSON 的双引号要写成 `""` 转义。UTF-8 编码。

### 方式 C：DBeaver 图形工具
连 `localhost:5433 / policy_fact / policy / policy123`，右键表"导入数据"。

## 六、录入后校验

```sql
-- 1. 没挂考点的题目（漏关联）
SELECT question_id, exam_year FROM exam_question q
WHERE NOT EXISTS (SELECT 1 FROM exam_question_kp r WHERE r.question_id=q.question_id);

-- 2. 考点实际命中频次（用于修正 frequency 字段）
SELECT k.kp_name, k.frequency AS 标记, count(r.question_id) AS 实际题数
FROM knowledge_point k
LEFT JOIN exam_question_kp r ON k.kp_id=r.kp_id
GROUP BY k.kp_name, k.frequency
ORDER BY 实际题数 DESC;

-- 3. 关联指向不存在的题目/考点（孤儿关联，应级联已清，复核用）
SELECT * FROM exam_question_kp r
LEFT JOIN exam_question q ON r.question_id=q.question_id
WHERE q.question_id IS NULL;
```

## 七、避坑

1. **options 用 JSONB 不用文本**——结构化才能让 AI 按选项号引用
2. **答案格式统一**——单选填 `A`，多选填 `ABD`（字母连写），判断填 `对/错`
3. **解析必填**——解析是客服答疑和小红书干货的核心素材，别只录答案
4. **案例题处理**——无客观选项时 options 填 null，材料写进 content
5. **频次要回填**——先按经验标 frequency，录够真题后用校验 2 的统计修正
