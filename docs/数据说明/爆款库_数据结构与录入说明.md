# 爆款样本库 — 数据结构与录入说明

> 小红书专属：客服不需要。用于内容生产系统的 few-shot 样本，让 AI 学你的爆款风格。
> 依赖：引用政策事实库的 `cert_basic`（证书），可空（非证书相关爆款可不挂证书）。

## 连接信息
- 库：`policy_fact`（容器 `policy-db`，宿主机 `localhost:5433`）
- 用户/密码：`policy` / `policy123`
- 导入命令：`docker exec -i policy-db psql -U policy -d policy_fact < 文件.sql`

## 一、表结构（单表）

只有 1 张表 `viral_post`。每条 = 一篇历史爆款笔记 + 它的数据表现。

### 字段说明

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| post_id | 主键 | 笔记ID | `vp_001` |
| platform | CHECK | 小红书/公众号/抖音/朋友圈 | 小红书 |
| cert_id | FK可空 | 涉及哪个证书 | `yj_jzs` |
| title | 文本 | **标题（爆款命脉，单独字段）** | 一建本科本专业3年能考吗？90%的人搞错了工作年限 |
| content | 文本 | 正文 | 最近好多姐妹问…… |
| cover_text | 文本 | 封面文案 | （小红书封面大字） |
| tags | JSONB | 话题标签 | `["一建","报考条件","备考"]` |
| topic_type | CHECK | 痛点/干货/身份/避坑/政策/其他 | 痛点 |
| post_date | DATE | 发布日期 | 2025-03-10 |
| url | 文本 | 原文链接（备查） | https://... |
| views | INT | 曝光 | 52000 |
| likes | INT | 点赞 | 4300 |
| collects | INT | 收藏 | 6100 |
| comments | INT | 评论数 | 180 |
| leads | INT | **带来咨询数（核心转化指标）** | 42 |
| is_viral | BOOL | 是否达标进库 | true |
| note | 文本 | 复盘备注（为什么爆） | 标题用痛点钩子+数字，评论区高频问报考 |

### 为什么这样设计

- **标题单独字段 + 三字索引**：标题决定 70% 流量，要能单独检索、单独学
- **tags 用 JSONB**：标签数量不定，结构化存便于按标签筛
- **指标拆成独立列**（views/likes/collects/leads）：能排序、能算转化率，比塞 JSON 强
- **leads 是核心**：曝光点赞是虚荣指标，**带来咨询数（leads）才是商业价值**，检索默认按 leads 降序
- **note 复盘字段**：记下"为什么爆"，是 few-shot 之外最值钱的经验沉淀

## 二、录入顺序

无依赖，单表直接录。但建议：
```
1. 收集历史爆款笔记（20-30 篇起步，越往后越全）
2. 补全数据指标（发布后 3-7 天回填 views/likes/collects/leads）
3. 填 topic_type 和 note（这两项决定 few-shot 质量）
```

> 冷启动期哪怕只有 20 篇，效果都比没有强十倍。先手动收集你账号最爆的 20-30 篇。

## 三、topic_type 选题类型怎么标

| 类型 | 特征 | 示例方向 |
|------|------|---------|
| 痛点 | 戳用户焦虑/困惑 | "90%的人搞错了工作年限" |
| 干货 | 整理类、收藏向 | "3年真题高频考点，收藏直接背" |
| 身份 | 具体人群代入 | "30岁宝妈在职备考一建" |
| 避坑 | 反面警示 | "别再被忽悠！消防挂靠真相" |
| 政策 | 政策解读/变动 | "2025一建报名时间定了" |
| 其他 | 不属于以上 | |

> 标准要统一，同一类爆款归同一 type，AI 才能按类型学风格。

## 五、录入方式

### 方式 A：SQL（少量，推荐起步用）
照上面格式写 INSERT。20-30 篇手写最快。

### 方式 B：CSV 批量
tags 是 JSONB，CSV 里写 JSON 字符串，双引号转义：
```
post_id,platform,cert_id,title,content,tags,topic_type,post_date,views,likes,collects,comments,leads,note
vp_003,小红书,yj_jzs,一建备考时间表,"在职备考怎么安排…","[""一建"",""备考"",""时间管理""]",干货,2025-05-01,60000,5000,9000,120,35,时间表类收藏高
```
导入：
```bash
docker exec -i policy-db psql -U policy -d policy_fact -c \
"\copy viral_post(post_id,platform,cert_id,title,content,tags,topic_type,post_date,views,likes,collects,comments,leads,note) \
FROM '/dev/stdin' WITH (FORMAT csv, HEADER true)" < viral_post.csv
```
> CSV 里 JSON 双引号写成 `""`。UTF-8 编码。

### 方式 C：DBeaver 图形工具
连 `localhost:5433 / policy_fact / policy / policy123`，右键表"导入数据"。

## 六、数据回流（这是爆款库的灵魂）

发布新笔记后要回填数据，让库越用越强：

```sql
-- 发布一周后回填数据（更新对应 post_id）
UPDATE viral_post SET
  views=65000, likes=5100, collects=9200, comments=140, leads=38,
  note='标题钩子有效，但正文太长掉完读率'
WHERE post_id='vp_003';

-- 达标的自动标记进库（leads>=10 视为爆款）
UPDATE viral_post SET is_viral=TRUE WHERE leads>=10;
```

**回流怎么用**：
- 每周/月用 SQL 统计哪类 topic_type、哪种标题钩子 leads 最高 → 输出爆款规律
- leads 达标的自动进 few-shot 样本池，AI 下次生成时引用
- leads 低的别进库，避免污染

```sql
-- 本月各选题类型转化对比
SELECT topic_type, count(*) AS 篇数, sum(leads) AS 总咨询, avg(leads) AS 篇均咨询
FROM viral_post WHERE is_viral=TRUE
GROUP BY topic_type ORDER BY 篇均咨询 DESC;
```

## 七、避坑

1. **标题比正文重要 10 倍**——录入时标题务必完整准确，它是学习重点
2. **leads 是核心指标**——别只看 views/likes，没带来咨询的"爆款"对业务无意义
3. **note 别省**——"为什么爆"的经验比笔记本身更值钱，是 AI 学不到的人肉洞察
4. **topic_type 标准统一**——同类归同 type，否则 few-shot 学乱
5. **冷启动先凑 20 篇**——少而精比多而杂强，先把自己最爆的笔记录全
6. **数据要回填**——不回流的库是死的，发布后必须回来填指标
