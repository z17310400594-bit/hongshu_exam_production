# P8 资料型引流策略化生成 MVP PRD

状态：根据 Grill Me 结论整理版  
适用分支：`feat/v2-knowledge-platform`  
执行原则：以“引流转化脚本”为中心，不以“固定卡片类型”为中心。

## 1. Grill Me 收束结论

本 PRD 以这段讨论结论为准：

1. 首期做资料型引流。
2. 系统推荐 + 人工可改。
3. 不固定死卡片类型，改为内容结构模板；内容结构模板由系统生成，同时必须支持人工修改编辑。
4. 最终仍输出小红书图文卡片。
5. 生成目标是 80%+ 可用成稿。
6. 不一键发布，保留人工审核。
7. 资料诱饵可以是拟态资料名。
8. 重点优化评论、私信、收藏等站内转化动作。
9. 专业内容只做信任背书，不做完整讲义。
10. 后续再扩展避坑型、计划型、焦虑型、案例型等内容类型。

关键产品判断：

小红书最终当然要输出卡片，但产品设计不要“以卡片为中心”，要“以引流转化脚本为中心”。卡片只是最后的呈现形式。

## 2. Problem Statement

当前 V2 可以生成小红书备考卡片，但旧逻辑偏固定卡片序列，例如：

```text
第1张封面
第2张计划
第3张计划
第4张科目
第5张资料
第6张须知
第7张 CTA
```

这种方式有两个核心问题：

1. 内容相似度高。每篇文章骨架一样，用户看几篇就会腻，平台也容易判定为低质模板化内容。
2. 转化目标被结构绑架。资料领取型、避坑型、学习计划型、焦虑型、案例型不应该都塞进同一套卡片序列。

完全自由生成也不可取：

- 运营不知道怎么控质量。
- Dify 输出会飘。
- 前端很难稳定渲染。
- 容易出现结构缺失、字段漂移、内容偏题。

所以 P8 的中间态是：

- 固定转化框架，不固定卡片内容。
- 固定渲染规范，不固定文章脚本。
- 固定首期打法，不一次性做全内容中台。

## 3. Product Goal

P8 要让运营生成“80%+ 可用的小红书资料型引流成稿”。

不是：

- 一键发布系统。
- 简单草稿生成器。
- 知识点讲义生成器。
- 资料摘要器。

而是：

- 系统生成可直接进入人工审核的成稿。
- 运营只做 5-10 分钟审核、微调、复制发布。
- 内容目标明确服务于公域流量转私域，但首期前端转化方式只暴露站内动作。
- 专业内容只承担信任背书。

## 4. 80%+ 可用成稿定义

生成结果达到 80%+，意味着：

- 标题钩子方向可用，不需要运营重写大方向。
- 内容结构完整，转化路径清楚。
- 资料诱饵明确，能支撑评论、私信、收藏等动作。
- 有少量真实专业内容支撑信任，但不把知识点全部讲完。
- CTA 明确，有评论关键词、私信引导或收藏提示。
- 运营只需要改个别词、资料名、评论关键词、敏感表达、账号风格话术。

不能低于 80%，否则运营还要重写结构、标题、CTA，提效失败。

也不追求 100%，因为：

- 100% 会导致过度模板化。
- 100% 会让运营失去把关权。
- 100% 技术成本高，投放效果仍然需要人判断。

## 5. 三层结构设计

### 5.1 第一层：内容目标

内容目标决定“为什么写这篇”。

首期只开放：

| code | 名称 | 目标 |
|---|---|---|
| `resource_lead` | 资料型引流 | 通过资料诱饵推动评论、私信、收藏 |

后续扩展：

| code | 名称 |
|---|---|
| `pitfall_lead` | 避坑型引流 |
| `plan_lead` | 计划型引流 |
| `anxiety_lead` | 焦虑型引流 |
| `case_lead` | 案例型引流 |
| `knowledge_preview` | 干货预览型 |

### 5.2 第二层：内容脚本

内容脚本决定“这篇文章如何转化”。

资料型引流的默认脚本：

| 脚本节点 | 作用 |
|---|---|
| `cover_hook` | 封面钩子，让用户点进来 |
| `pain_point` | 痛点，说明为什么现在需要资料 |
| `solution` | 解决方案，说明资料怎么帮用户 |
| `knowledge_preview` | 干货预览，用少量专业点建立信任 |
| `resource_bait` | 资料诱饵，展示三色笔记、考点 PDF、打卡表等 |
| `receive_method` | 领取方式，引导评论、私信、收藏 |
| `audit_note` | 审核提示，给运营检查风险 |

注意：这些是脚本节点，不是固定卡片类型。

### 5.3 第三层：卡片渲染

卡片渲染只负责把脚本拆成小红书图文卡片。

规则：

- 系统推荐 5-8 张卡。
- 卡片数量可手动改。
- 每张卡可编辑。
- 非封面不强制大标题。
- 最终可以复制正文、导出图片、进入审核。

## 6. 首期模板：资料型引流

资料型引流的系统推荐结构：

```text
封面：三色笔记整理好了
痛点：宝妈没时间，不知道背哪里
方法：每天用这 3 份资料
干货预览：先放 3 个高频点
资料清单：三色笔记 / 考点 PDF / 打卡表
领取方式：评论关键词 / 私信 / 收藏
```

运营必须可以编辑这套结构。编辑范围包括：

- 增删脚本节点。
- 调整脚本节点顺序。
- 修改每个脚本节点的目的说明。
- 修改系统推荐的卡片数量。
- 修改脚本节点最终拆成的卡片标题和正文。

系统推荐是默认值，不是锁死模板。

资料诱饵可以是拟态资料名，例如：

- 三色笔记
- 高频考点 PDF
- 30 天打卡表
- 历年真题解析
- 易混点表
- 高频章节清单
- 速记口诀
- 思维导图

边界：

- 不写“官方资料”。
- 不写“押题必中”。
- 不承诺“包过”。
- 不替运营承诺真实发送资料。
- 是否实际发送资料不在 P8 范围内。

## 7. 用户可控项

前端左侧控制台应提供：

| 控制项 | 要求 |
|---|---|
| 证书项目 | 沿用当前逻辑，从数据库证书表读取并以下拉展示，例如执业药师 |
| 目标人群 | 宝妈、上班族、零基础、非科班等 |
| 内容目标 | 首期默认资料型引流 |
| 内容结构模板 | 系统生成默认结构，运营可修改节点、顺序和内容 |
| 资料诱饵 | 系统推荐，可人工改 |
| 评论关键词 | 系统推荐，可人工改 |
| 私信口径 | 系统推荐，可人工改 |
| 卡片数量 | 系统推荐，可人工改 |
| 内容结构 | 系统推荐，可人工改 |
| 补充要求 | 人工输入 |

非技术用户不应看到：

- 请求体。
- Dify API 信息。
- 数据库字段。
- 调试状态机。

## 8. 前端原型要求

页面保持当前工作台风格：

- 左侧竖列是策略控制台。
- 右侧是小红书卡片预览。
- 右侧展示“内容脚本 → 自动拆卡”的关系。
- 内容结构模板必须可编辑，不是只读预设。
- 每张卡允许编辑。
- 支持复制正文。
- 支持进入人工审核。

UI 文案不要叫“卡片类型预设”，应改为：

```text
内容结构模板
```

## 9. 后端与 Dify 要求

后端/Dify 不应被写死为固定卡片序列。

后端应该接收：

| 字段 | 含义 |
|---|---|
| `contentGoal` | 内容目标，例如资料型引流 |
| `structureTemplate` | 内容结构模板，例如 `resource_lead_v1` |
| `scriptNodes` | 内容脚本节点 |
| `leadAssets` | 资料诱饵 |
| `commentKeyword` | 评论关键词 |
| `conversionMode` | 评论、私信、收藏 |
| `cardCount` | 推荐或人工修改后的卡片数量 |
| `manualBrief` | 人工补充要求 |

Dify 负责生成当前脚本节点内容，不负责复杂清洗。

代码端负责：

- 字段归一化。
- 空内容兜底。
- JSON/文本混合解析。
- `undefined` 防护。
- 将脚本节点拆成可渲染卡片。

## 10. Acceptance Criteria

P8 首期完成必须满足：

1. 前端不再使用“卡片类型预设”作为核心入口，而是使用“内容结构模板”。
2. 首期只开放资料型引流模板。
3. 证书项目沿用当前数据库下拉逻辑，不在 P8 写死。
4. 系统能生成内容结构模板，且运营可修改节点、顺序和说明。
5. 系统能推荐资料诱饵，且运营可改。
6. 系统能推荐评论关键词，且运营可改。
7. 系统能推荐卡片数量，且运营可改。
8. 后端/Dify 接收的是内容目标、内容脚本、资料诱饵，而不是固定卡片序列。
9. 最终仍输出小红书图文卡片。
10. 卡片预览可编辑。
11. 支持复制正文。
12. 支持进入人工审核。
13. 生成内容 80%+ 可用，运营 5-10 分钟内可完成审核和微调。
14. 专业内容只做信任背书，不做完整讲义。
15. CTA 明确体现评论、私信或收藏等站内动作。
16. 不出现 `undefined`。
17. 不破坏当前 V2 演示链路。

自测报告路径：

```text
docs/implementation/reports/P8_RESOURCE_LEAD_MVP_SELF_TEST.md
```

## 11. Out of Scope

- 不一键发布。
- 不做自动私信。
- 不做自动外部联系方式引导。
- 不做真实资料自动发送。
- 不做小红书数据抓取。
- 不做投放归因。
- 不做完整讲义生成。
- 不一次性上线多种内容类型。

## 12. Future Expansion

资料型引流跑通后，再用同一套三层结构扩展：

- 避坑型：误区 → 正确做法 → 资料领取。
- 计划型：阶段计划 → 打卡表 → 资料领取。
- 焦虑型：倒计时压力 → 补救路径 → 资料领取。
- 案例型：用户场景 → 解决路径 → 资料领取。

扩展时新增的是内容结构模板，不是硬编码更多固定卡片类型。
