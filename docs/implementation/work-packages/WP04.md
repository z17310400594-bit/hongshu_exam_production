## 最低验收矩阵

1. asset、asset_version、fragment 的 FK/CHECK/UNIQUE、级联行为逐项失败测试。
2. 同一 asset 创建 v1/v2 成功；同版本号重复失败。
3. published/approved 版本更新 object_key、SHA、正文等不可变字段失败。
4. 相同 SHA256 返回已有文件/明确重复状态，不产生第二份对象。
5. 上传对象键由服务生成，调用方不能注入越权 prefix 或路径穿越。
6. restricted 对象只能写入独立 prefix；public/internal 不得混用该 prefix。
7. 下载 URL 必须短时有效；无 ACL、错误组织、匿名请求均拒绝，且拒绝前不调用 MinIO presign。
8. MinIO 不可用时数据库不得留下伪成功版本；测试事务/补偿行为。
9. fragment 能确定关联 asset_version、父片段、顺序、标题、page_from/page_to；孤儿版本和非法页码失败。
10. 使用独立测试 bucket/prefix；测试结束清理对象、测试库、服务和端口。
11. migration metadata/schema `diff_count=0`，新增模块可冷导入，完整门禁及前端基线通过。

## 禁止事项

- 禁止只建三张表而省略 MinIO、权限、不可变和去重行为。
- 禁止把永久公开 URL 当作短时下载 URL。
- 禁止在日志、响应或对象键中泄露 restricted 标题、正文或真实内部路径。
- 禁止使用 mock-only 正向测试；至少一个测试需连接真实 MinIO 测试容器/实例。
- 禁止在报告中存在 pending 同时填写 Overall PASS。
