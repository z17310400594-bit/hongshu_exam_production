# 部署、迁移与验收

## 一、推荐部署形态

第一期采用 Docker Compose + 模块化单体，避免过早微服务化：

```text
nginx                 HTTPS、反向代理
web                   Taro H5 静态资源
api                   FastAPI/NestJS 业务 API
worker                文件解析、切片、索引任务
postgres:15           主数据库
pgbouncer             连接池
minio                 原文件对象存储
redis                 任务队列、缓存
dify                  工作流和模型调用
```

全文检索初期使用 PostgreSQL；向量量较小时可用 pgvector。若真实评测证明 PostgreSQL 中文检索不足，再引入 Elasticsearch/OpenSearch。不要先按想象增加组件。

## 二、仓库调整

建议加入：

```text
db/
  migrations/
  seeds/
  tests/
  staging/
api/
worker/
infra/
  compose.yaml
  nginx/
docs/
  architecture/
```

DDL 不能继续只放桌面目录。每次 schema 修改都通过 migration，禁止人工改生产表。

## 三、安全配置

1. 立即轮换现有仓库和前端中出现过的数据库密码、Dify API Key。
2. 浏览器不得持有 Dify Key；前端只能调用企业 API/BFF。
3. 密钥使用环境变量或密钥管理服务，不提供代码默认值。
4. API 使用 HTTPS、身份认证、RBAC/ACL、限流和请求体上限。
5. PostgreSQL 应区分 migration、api_read、api_write、worker 角色，默认撤销 public schema 权限。
6. restricted 文件使用独立 bucket/prefix、短时签名 URL，并记录下载审计。
7. 外部模型调用前检查 `allowed_use` 与 `confidentiality`；restricted 默认禁止外发。

## 四、迁移步骤

### 阶段 0：冻结与备份

- 对现有数据库执行 `pg_dump`；
- 备份桌面 CSV、SQL、说明文档并计算 SHA256；
- 记录现有 API 输出样本和 100 条典型查询；
- 禁止继续在旧 CSV 中随意增加编码。

### 阶段 1：清洗主数据

- 修复重复的 `sched_pharmacist_2026`；
- 区分 `pharmacist` 与 `pharmacist_licensed`；
- 修复多个证书错误共用“一建”的简称和主管机构；
- 建立旧 ID → 新 code 映射表；
- 补全所有政策事实的真实条款来源；无法确认来源的记录只能进入 draft。

### 阶段 2：建立 V2 并行库

- 运行 schema migrations；
- 建组织、集合、ACL 和主数据；
- 建 staging 表和导入校验器；
- 先迁资产、版本、片段，再迁知识点和事实关系；
- 禁止直接修改旧表。

### 阶段 3：数据回填

迁移顺序：

```text
组织/权限
→ 证书/别名/科目
→ 知识集合/资产/版本/片段
→ 政策版本/条款
→ 知识点与片段映射
→ 报考规则与证据
→ 考试场次/阶段/分数规则
→ 教材/章节
→ 试卷/题目
→ 运营内容/指标快照
```

### 阶段 4：双读验证

- API 同时读取旧库和 V2；
- 对相同请求比较证书解析、条件判断、考试日期和引用；
- 差异写入 comparison 表，不影响用户；
- V2 结果达到验收指标后切读流量。

### 阶段 5：切换与退役

- 切换前再次增量同步；
- API feature flag 切到 V2；
- 旧库保持只读至少两个发布周期；
- 确认无回滚需求后归档旧库，不立即删除。

## 五、自动化测试

### 数据库测试

- PK、UK、FK、CHECK 都有失败用例；
- 政策版本有效期不得非法重叠；
- published 事实必须 approved 且至少有一条 primary evidence；
- restricted 数据必须存在 ACL；
- 所有外键列都有适合的索引；
- migration 从空库可重复构建完整 schema。

### API 测试

- 精确别名、常用别名、歧义别名；
- 普通路径、老人老办法、地区例外；
- 多阶段考试；
- 已废止政策不进入当前回答；
- 无权限用户检索不到 restricted 数据，响应和日志都不能泄漏摘要；
- 数据库错误返回 5xx，不得伪装成空数据。

### 检索与 AI 评测

指标：

| 指标 | 初期目标 |
|---|---|
| 结构化实体抽取准确率 | ≥95% |
| 报考规则判断准确率 | ≥99% |
| Recall@5 | ≥90% |
| 引用来源正确率 | ≥98% |
| 事实数字准确率 | ≥99% |
| restricted 越权泄漏率 | 0 |
| 无引用的政策结论 | 0 |

## 六、备份、监控和回滚

- 每日逻辑备份、定期全量备份并执行恢复演练；
- 开启 `pg_stat_statements`；
- 监控慢查询、连接池、导入失败率、解析队列、索引滞后；
- 每个 migration 提供向前修复或可验证回滚方案；
- 对政策发布、权限变更、AI 批量生成建立业务告警。

## 七、建议实施节奏

1. 第 1 周：清洗、术语和编码体系、权限分级。
2. 第 2 周：V2 核心 schema、migration、staging。
3. 第 3 周：资产、政策、知识点、考试数据迁移。
4. 第 4 周：API/BFF、ACL 检索、前端联调。
5. 第 5 周：双读、评测、安全和恢复演练。
6. 第 6 周：灰度切换、旧库只读。
