# 企业知识资产平台 V2：设计与实施交接包

## 1. 目标

将现有“政策事实库 + 真题库 + 爆款库”升级为部门共享的企业教育内容与知识资产平台，同时支持：

- 政策、法规、考试安排等高时效事实；
- 教材、教辅、讲义、课程资料；
- 试卷、题目、答案、解析、评分规则；
- 跨教材、跨考试共享的标准知识点体系；
- 公司私有资料作为 AI 内容生成的受控参考资料；
- 小红书文章、卡片、教材草稿、模拟卷等生成内容；
- 来源引用、版本、审核、权限、版权和完整审计。

平台不是“一张大表”，而是一个统一逻辑底座，按领域拆分 schema：

| Schema | 职责 |
|---|---|
| `iam` | 用户、部门、角色、权限 |
| `core` | 证书、科目、地区、通用字典 |
| `knowledge` | 知识资产、版本、片段、知识点、知识关系 |
| `policy` | 政策文档、版本、条款、结构化政策事实 |
| `content` | 教材、教辅、章节、内容版本 |
| `assessment` | 试卷、题目、解析、知识点映射 |
| `generation` | AI 生成任务、引用、输出、审核 |
| `analytics` | 内容发布与指标快照 |
| `ingestion` | CSV/文件导入批次与校验错误 |
| `audit` | 检索、下载、生成、审批审计 |

## 2. 核心原则

1. PostgreSQL 是结构化事实、元数据、关系和权限的事实源。
2. PDF、Word、图片等原文件放 MinIO/S3；数据库只保存对象键、哈希和抽取文本。
3. 全文索引和向量索引都是可重建的派生数据，不得成为唯一事实源。
4. 每条政策事实、教材结论和 AI 输出必须能引用具体资产版本与片段。
5. 原始资料不可覆盖；修订产生新版本。
6. AI 输出默认是草稿，审核通过后才可成为正式知识资产。
7. 检索前完成权限过滤；不能先取回敏感内容再在模型侧过滤。
8. 生成内容继承所有输入资料中的最高保密等级。
9. 所有业务主键使用 `bigint generated always as identity`；跨系统交换使用唯一 `code`。
10. CSV 只能进入 staging，校验全通过后在单事务内写入正式表。

## 3. 技术架构

```text
Taro 前端
   │ HTTPS + 用户令牌
   ▼
业务 API / BFF
   ├─ 权限校验、限流、参数校验
   ├─ PostgreSQL：事实、关系、版本、ACL
   ├─ MinIO/S3：PDF/Word/图片原件
   ├─ 检索服务：全文 + 向量 + 权限条件
   └─ Dify/LLM：只接收授权后的片段

后台管理端
   ├─ 资料上传与解析
   ├─ 知识点标注
   ├─ 政策事实录入
   ├─ 双人复核/发布
   └─ 导入错误与审计查询
```

不得由浏览器直接调用 Dify 或数据库 API。现有前端中暴露的 Dify Key 和数据库默认密码必须轮换。

## 5. 明确不做

- 不把所有原文和业务字段塞入一个万能 JSONB 表；
- 不把 Dify 知识库当主数据库；
- 不允许未经审核的 AI 内容反向污染正式知识库；
- 不在第一期引入复杂微服务，初期可采用模块化单体 API；
- 不在没有真实评测集前决定 Elasticsearch 或大型向量数据库。
