# 数据模型与字段字典

## 一、公共字段约定

正式业务表原则上包含：

| 字段 | 类型 | 含义 |
|---|---|---|
| `id` | bigint identity | 内部主键 |
| `code` | text unique | 外部稳定业务编码 |
| `status` | text | 生命周期状态 |
| `created_at` | timestamptz | 创建时间 |
| `created_by` | bigint | 创建人 |
| `updated_at` | timestamptz | 更新时间 |
| `updated_by` | bigint | 更新人 |

业务分类优先使用受控字典表或 CHECK，不建议使用难以迁移的 PostgreSQL ENUM。

## 二、组织、权限与知识集合

### `iam.organization_unit`

部门树。教材部、教辅部、运营部等均为组织节点。

| 字段 | 含义 |
|---|---|
| `code` | 部门编码 |
| `name` | 部门名称 |
| `parent_id` | 上级部门 |
| `status` | active/inactive |

### `knowledge.collection`

知识集合是授权和检索的最小边界，例如“政策公开库”“教材部内部资料”“消防项目机密资料”。

| 字段 | 含义 |
|---|---|
| `code` | 集合编码 |
| `name` | 集合名称 |
| `owner_org_id` | 责任部门 |
| `confidentiality` | public/internal/confidential/restricted |
| `default_allowed_use` | retrieval/generation/internal_only 等 |

### `knowledge.collection_acl`

| 字段 | 含义 |
|---|---|
| `collection_id` | 知识集合 |
| `principal_type` | user/role/org |
| `principal_code` | 用户、角色或部门编码 |
| `permission` | read/contribute/review/admin |

API 必须把 ACL 条件加入 SQL/检索查询，不能在返回结果后过滤。

## 三、证书和科目主数据

### `core.certificate`

| 字段 | 含义 |
|---|---|
| `code` | 稳定编码，如 `cls1_constructor` |
| `name` | 正式名称 |
| `category_code` | 准入类/水平评价类等 |
| `issuing_authority` | 颁发机构 |
| `exam_authority` | 考试组织机构 |
| `nationwide` | 是否全国有效 |

### `core.certificate_alias`

证书简称、俗称、历史名称。`normalized_alias` 全局唯一，解决模糊匹配随机命中。

### `core.exam_subject`

| 字段 | 含义 |
|---|---|
| `certificate_id` | 所属证书 |
| `code` | 科目编码 |
| `name` | 科目名称 |

合格线不放在科目主表，放在年度考试规则中。

## 四、统一知识资产

### `knowledge.asset`

政策、教材、讲义、私有文档、试卷等资料的统一入口。

| 字段 | 含义 |
|---|---|
| `code` | 资产业务编码 |
| `asset_type` | policy/textbook/handout/private/paper/manual |
| `title` | 资产标题 |
| `collection_id` | 所属知识集合及安全边界 |
| `owner_org_id` | 责任部门 |
| `confidentiality` | 保密等级 |
| `copyright_owner` | 版权所有人 |
| `allowed_use` | 允许检索、生成、训练或仅内部查看 |
| `status` | draft/reviewed/published/deprecated |

### `knowledge.asset_version`

| 字段 | 含义 |
|---|---|
| `asset_id` | 资产 |
| `version_no` | 版本号 |
| `object_key` | MinIO/S3 原文件键 |
| `mime_type` | 文件类型 |
| `extracted_text` | 抽取后的全文，可为空 |
| `content_sha256` | 去重、审计和防篡改哈希 |
| `valid_during` | 有效期 |
| `review_status` | pending/approved/rejected |
| `reviewed_by/at` | 审核人和时间 |

### `knowledge.fragment`

可引用、可检索的最小片段。

| 字段 | 含义 |
|---|---|
| `asset_version_id` | 所属资产版本 |
| `fragment_code` | 片段编码 |
| `fragment_type` | chapter/section/clause/page/table |
| `parent_id` | 父片段 |
| `sequence_no` | 顺序 |
| `heading` | 标题 |
| `content` | 片段内容 |
| `page_from/page_to` | 页码证据 |
| `search_tsv` | 全文检索派生列 |

向量表应记录 `embedding_model`、`embedding_version`，换模型后可并行重建。

## 五、统一知识点体系

### `knowledge.knowledge_point`

| 字段 | 含义 |
|---|---|
| `code` | 全局知识点编码 |
| `name` | 标准名称 |
| `parent_id` | 知识点树父节点 |
| `domain_code` | 建筑/消防/医药/法律等领域 |
| `cognitive_level` | remember/understand/apply/analyze |
| `description` | 标准定义 |

### `knowledge.knowledge_point_relation`

表达 prerequisite、related、contains、similar 等关系。

### `knowledge.knowledge_point_scope`

知识点与证书、科目、课程标准版本的多对多适用范围。知识点不再被某个证书独占。

### `knowledge.fragment_knowledge_point`

资料片段与知识点关系，字段包含 `relation_role`、`confidence`、`review_status`、`reviewed_by`。机器标注只能进入 pending，人工通过后才能用于高可信生成。

## 六、政策领域

### `policy.document` / `policy.document_version` / `policy.clause`

政策业务表关联到通用资产版本，但额外保存文号、发布机构、修订替代关系和条款定位。

### `policy.eligibility_rule`

每行表示一条 AND 路径，多行表示 OR。核心字段：

- `qualification_level`：初级/中级/高级/首考/增项；
- `route_code`：normal/grandfathered/title_substitute；
- `degree_level_code`、`major_category_code`、`education_type_code`；
- `min_total_work_months`、`min_relevant_work_months`；
- `admission_before`：老人老办法截止日期；
- `region_code`、`valid_during`；
- `extra_conditions jsonb`：仅承载低频例外，不替代核心字段；
- `review_status`：只有 approved 可供生产查询。

### `policy.eligibility_rule_evidence`

真实外键连接 `eligibility_rule` 和 `policy.clause`，支持 primary/supporting/exception。其他政策事实同样建立各自的证据关联表，禁止无外键多态关联。

## 七、考试日程与合格线

### `assessment.exam_event`

证书 × 年份 × 地区唯一。

### `assessment.exam_phase`

报名、实践、笔试、查分等多个阶段，每个阶段都有起止日期。

### `assessment.subject_score_rule`

年度考试场次下某科目的满分、合格分和规则证据。约束 `pass_mark BETWEEN 0 AND full_mark`。

## 八、教材与教辅

### `content.product`

教材、教辅、讲义、课件等产品主记录，包含责任部门、适用课程标准和状态。

### `content.product_version`

drafting/reviewing/approved/published 生命周期；禁止原地覆盖已发布版本。

### `content.chapter`

章节树、正文、顺序。

### `content.chapter_knowledge_point`

章节与知识点的关系，`teaching_role` 可为 core/example/extension/exercise。

## 九、题库与试卷

### `assessment.paper`

真题、模拟卷、章节练习；保存证书、科目、年份、来源资产、责任部门和审核状态。

### `assessment.question`

保存题号、题型、题干、JSONB 选项、JSONB 答案、解析、难度、来源。约束 JSON 类型和难度范围。

### `assessment.question_knowledge_point`

题目与知识点多对多，保存 primary/secondary 角色与分值权重。

## 十、AI 生成与引用

### `generation.run`

记录应用、用户、模型供应商、模型名、prompt 版本、安全等级和状态。

### `generation.citation`

记录生成任务实际使用的 `fragment_id`、引用顺序和用途。

### `generation.output`

文章、卡片、教材草稿、试题等输出，状态为 draft/reviewed/approved。安全等级取输入片段最高等级。

## 十一、内容运营指标

### `analytics.post`

保存平台、外部文章 ID、标题、正文、知识点、发布信息。

### `analytics.post_metric_snapshot`

按 `collected_at` 保存曝光、点赞、收藏、评论、线索等快照。文章是否爆款应由规则计算，不应默认 true。

## 十二、导入与审计

### `ingestion.import_batch`

文件名、哈希、操作者、状态、总行数、成功数、失败数。

### `ingestion.validation_error`

行号、字段、错误码、错误信息。任一 P0 错误必须使批次整体回滚。

### `audit.event`

记录用户对资产的检索、查看、下载、生成、审批和权限变更。restricted 资料的所有访问必须审计。
