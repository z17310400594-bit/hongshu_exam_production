# CSV 与测试数据模板

## 一、导入原则

1. 文件统一 UTF-8、逗号分隔、首行列名。
2. CSV 使用业务 `code` 引用，不暴露数据库 bigint ID。
3. 原始数据先导入 staging；校验通过后解析 code 并写正式表。
4. 空字符串、0、未知是三种不同语义，不得混用。
5. 日期使用 `YYYY-MM-DD`，时间使用带时区 ISO 8601。
6. JSON 字段必须是合法 JSON；CSV 内双引号按 CSV 规则转义。
7. 每个文件配套 `valid/`、`invalid/` 和 `expected_errors.csv`。

## 四、无效测试数据

至少准备：

| 文件 | 预期失败 |
|---|---|
| `duplicate_alias.csv` | 同一 normalized_alias 指向多个证书 |
| `orphan_fragment.csv` | 资产版本不存在 |
| `orphan_rule_evidence.csv` | 规则或条款不存在 |
| `overlapping_policy_version.csv` | 同一政策发布版本有效期重叠 |
| `negative_work_months.csv` | 工作月份为负 |
| `phase_end_before_start.csv` | 阶段结束早于开始 |
| `pass_mark_over_full.csv` | 合格分高于满分 |
| `question_bad_json.csv` | 选项或答案不是合法 JSON |
| `question_missing_kp.csv` | 知识点不存在 |
| `restricted_acl_violation.csv` | 无权限用户读取 restricted 集合 |
| `unreviewed_generation.csv` | 未审核资料用于正式生成 |
| `expired_policy_reference.csv` | 生成引用已失效政策 |

## 五、验收规模

第一阶段不要追求全量。建议：5 种证书、20 份政策、2 本教材、100 个知识点、200 道题、30 份私有资料、30 篇运营文章。用 100 条真实查询建立人工标注评测集，分别统计结构化查询准确率、检索 Recall@K、引用正确率、越权泄漏率和生成事实准确率。
