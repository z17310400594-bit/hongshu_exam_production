# P8 小红书策略化生成 MVP 计划书

> 状态：pending  
> 建议执行顺序：P5 真实 Dify 链路可跑通后，先做 P8，再进入 P7 内部灰度。  
> 核心目标：把当前“固定卡片模板生成”升级为“小红书内容策略生成”，解决“写死太像、写松太散”的问题。

## 1. 背景与问题

当前 V2 生成链路已经做到：

- 前端不直接持有 Dify key；
- 后端负责调用模型网关/Dify；
- 生成结果能落入 `generation.run / citation / output`；
- 前端能展示卡片并导出；
- 后端已对 Dify 空返回、字段漂移、`undefined` 等问题做了兼容。

但当前内容结构仍然偏“工程模板”：

- 卡片类型围绕 `cover / plan / priority / resources / cta` 固定展开；
- 前端渲染逻辑依赖 `title / subtitle / days / items / study_material`；
- Dify 一旦自由发挥，字段容易漂移；
- Dify 如果被约束太死，生成内容又会像同一篇文章换皮；
- 对小红书考试类爆款常见结构支持不足，比如“倒计时救命计划、资料包钩子、分值优先级、避坑提醒、身份场景”。

本阶段要做的是一个可控的 MVP，不是完整内容中台。

## 2. 产品目标

P8 要让用户可以从前端选择“小红书内容打法”，然后系统按策略生成一组结构稳定、但表达可变化的卡片。

目标效果：

1. 用户不再只选择“几张卡片”，而是选择“内容策略”。
2. 前端提供有限但有效的钩子模板，避免模型瞎写标题。
3. 后端把策略转换为卡片角色序列，保持生成结构可控。
4. Dify 仍按单卡生成，降低长文空返回和字段混乱风险。
5. 前端继续兼容旧字段，不因 P8 破坏当前已跑通的生成链路。
6. 先用“执业药师”跑通真实小红书风格生成，不追求所有证书一次性完美。

## 3. 非目标

P8 明确不做：

- 不改数据库 schema；
- 不做策略管理后台；
- 不做复杂拖拽编辑器；
- 不做多账号投放、发布、评论私信自动化；
- 不把小红书平台数据抓取纳入本阶段；
- 不在前端保存 Dify key；
- 不让浏览器直接调用 Dify、MinIO、数据库；
- 不要求一次支持所有证书的高质量模板；
- 不把资料领取做成强营销闭环。

## 4. 用户故事

1. 作为运营人员，我希望选择“倒计时救命型”，让系统生成“如果从今天开始备考，直接照这个学”的内容。
2. 作为运营人员，我希望选择“资料清单型”，让系统生成更容易收藏和评论要资料的内容。
3. 作为运营人员，我希望选择“分值优先型”，让系统突出高频章节和优先级，而不是平均罗列知识点。
4. 作为运营人员，我希望选择“上班族/宝妈/零基础”等人群，让内容更像对特定用户说话。
5. 作为运营人员，我希望保留现有生成、审核、导出流程，不因为策略化生成重新学习一套工具。
6. 作为内容负责人，我希望生成结构稳定，避免出现 `undefined`、空字段、卡片类型错乱。
7. 作为内容负责人，我希望每张卡片承担明确传播任务，比如封面钩子、考试事实、倒计时计划、资料包、行动引导。
8. 作为后端维护者，我希望新增策略字段不影响旧接口和旧卡片序列。
9. 作为验收 Agent，我希望能按清晰矩阵验证策略字段是否传入、Dify prompt 是否收到、前端是否正确展示。

## 5. P8 MVP 范围

### 5.1 内容策略

第一版只支持 5 个策略：

| 策略 code | 名称 | 适用场景 | 默认卡片角色 |
|---|---|---|---|
| `countdown_rescue` | 倒计时救命型 | 临近考试、还没开始、需要照抄计划 | 封面钩子、考试事实、倒计时计划、分值优先级、高频章节、资料清单、做题技巧、行动引导 |
| `score_priority` | 分值优先型 | 考前冲刺、需要先抓高分章节 | 封面钩子、分值优先级、高频章节、做题技巧、资料清单、行动引导 |
| `resource_pack` | 资料清单型 | 资料领取、收藏、评论转化 | 封面钩子、考试事实、资料清单、高频章节、避坑提醒、行动引导 |
| `zero_base_plan` | 零基础保姆型 | 新手、非科班、完全没思路 | 封面钩子、考试事实、阶段计划、高频章节、资料清单、避坑提醒、行动引导 |
| `working_parent` | 上班族/宝妈型 | 时间少、碎片化学习 | 封面钩子、时间安排、分值优先级、高频章节、资料清单、行动引导 |

### 5.2 钩子模板

第一版只支持 6 个钩子：

| 钩子 code | 模板方向 |
|---|---|
| `if_start_today` | 假如你从今天/某日期开始备考，直接照这个学 |
| `days_left_rescue` | 只剩 N 天，还没开始的先看这张表 |
| `stop_average_effort` | 别再平均用力，先拿下这些高频章节 |
| `resource_do_not_buy_wrong` | 资料别乱买，这几份够用了 |
| `zero_base_no_panic` | 零基础别慌，按这个顺序来 |
| `busy_people_plan` | 宝妈/上班族每天 N 小时这样安排 |

### 5.3 卡片角色

P8 不要求立即删除旧 `CardType`，而是在旧结构上增加“角色”概念。

第一版角色：

| 角色 code | 作用 |
|---|---|
| `cover_hook` | 封面点击钩子，只负责吸引点击 |
| `exam_facts` | 考试时间、报名入口、考试形式、科目等事实 |
| `countdown_plan` | 按日期或阶段拆备考计划 |
| `score_priority` | 科目/章节/题型优先级和分值 |
| `key_chapters` | 高频章节、核心考点、知识点 |
| `resource_pack` | 资料清单、打印清单、工具包 |
| `exam_tips` | 做题技巧、记忆口诀、避坑提醒 |
| `cta` | 收藏、评论、私信、领取资料等行动引导 |

兼容策略：

- 发送给后端的 `cardSequence` 可以先继续使用字符串数组；
- 新角色可以作为新的字符串值进入 `cardSequence`；
- 后端归一化时保留 `type`，并额外透传 `role`；
- 前端如果不识别 `role`，仍按旧字段降级展示。

## 6. 建议数据契约

### 6.1 前端请求新增字段

在 `/api/v2/generations` 的 `inputs` 中新增：

| 字段 | 类型 | 含义 |
|---|---|---|
| `contentStrategy` | string | 内容策略 code |
| `hookPattern` | string | 钩子模板 code |
| `contentGoal` | string | 内容目标：收藏、评论、私信、转化、纯干货 |
| `ctaMode` | string | 行动引导方式：收藏、评论领资料、私信、无强转化 |
| `dailyHours` | number/string | 每日可学习时长 |
| `startDate` | string | 备考开始日期 |
| `tone` | string | 语气：焦虑型、稳妥型、陪伴型、干货型 |

已有字段继续保留：

- `examName`
- `examDate`
- `targetAudience`
- `theme`
- `role`

### 6.2 生成结果建议结构

P8 MVP 继续支持旧字段：

- `type`
- `title`
- `subtitle`
- `days`
- `items`
- `study_material`
- `qrcode_url`
- `citations`
- `mentor_note`

同时允许新增：

- `role`
- `hook`
- `modules`

`modules` 本阶段只作为可选增强，不要求前端完全重构。若 Dify 返回 `modules`，后端可先保留；前端第一版可以只使用旧字段展示。

## 7. 前端改造计划

### 7.1 类型层

修改目标：

- 增加 `ContentStrategy`、`HookPattern`、`ContentGoal`、`CtaMode` 类型；
- `CardData` 增加可选 `role`、`hook`、`modules`；
- `DifyGenerateParams` 增加 P8 输入字段；
- 保留旧 `CardType`，避免一次性重构所有卡片组件。

### 7.2 常量层

新增策略常量：

- 策略名称；
- 策略说明；
- 默认钩子；
- 默认卡片角色序列；
- 推荐目标人群；
- 推荐内容目标。

新增钩子常量：

- 钩子 code；
- 展示文案；
- 适用策略；
- 示例标题。

### 7.3 状态层

在生成 store 中新增：

- 当前策略；
- 当前钩子；
- 当前内容目标；
- 当前 CTA 模式；
- 每日学习时长；
- 备考开始日期；
- 语气。

选择策略时自动更新默认卡片序列，但允许用户再微调数量和顺序。

### 7.4 页面层

在现有生成表单中增加一个“小红书策略”区块：

1. 内容策略；
2. 钩子模板；
3. 目标人群；
4. 每日学习时长；
5. 内容目标；
6. 转化方式；
7. 语气。

页面不要求一次性做复杂交互。MVP 可用标签按钮 + 简单输入框。

### 7.5 展示层

MVP 展示要求：

- 封面只显示封面主钩子；
- 非封面卡不显示大标题，避免用户之前反馈的“每张都有标题很奇怪”；
- 若卡片角色是资料清单，优先渲染为清单；
- 若卡片角色是分值/优先级，优先渲染为列表；
- 若字段缺失，显示空白或兜底文案，不允许出现 `undefined`。

## 8. 后端改造计划

### 8.1 请求接收

`V2GenerationRequest.inputs` 当前是 dict，P8 不需要改 schema。

后端需要做：

- 对 P8 字段做默认值；
- 将 `contentStrategy / hookPattern / contentGoal / ctaMode / dailyHours / startDate / tone` 透传给 model gateway；
- 若前端未传 P8 字段，保持旧生成逻辑。

### 8.2 卡片序列归一化

新增策略转角色序列逻辑：

- 如果请求传了明确 `cardSequence`，优先使用请求；
- 如果传了 `contentStrategy` 但没有 `cardSequence`，后端按策略生成默认角色序列；
- 如果两者都没有，继续使用当前默认序列。

### 8.3 Dify payload

传给 Dify 的 payload 要包含：

- 当前单卡 `role/type`；
- 完整 `contentStrategy`；
- 完整 `hookPattern`；
- 目标用户；
- 考试时间；
- 倒计时；
- 引用资料摘要；
- 禁止输出无关卡片；
- 禁止输出空内容；
- 要求旧字段可渲染。

### 8.4 结果归一化

继续保留当前已有归一化策略，并新增：

- `role` 透传；
- 新角色映射到旧前端可渲染字段；
- `resource_pack` 返回的字符串列表归一化为 `items`；
- `score_priority/key_chapters/exam_tips` 统一归一化为 `items`；
- `countdown_plan` 统一归一化为 `days`；
- 空标题、空 subtitle、空列表不生成 `undefined`。

## 9. Dify 工作流改造计划

P8 仍然坚持“单卡生成”，不要回到一次性长文生成。

原因：

- 长文更容易超过 120s；
- 长文更容易出现空节点；
- 单卡失败可以重试；
- 单卡更容易定位是哪一张卡质量不好。

Dify prompt 需要新增：

1. 识别 `contentStrategy`；
2. 识别 `hookPattern`；
3. 识别当前 `role/type`；
4. 每次只生成当前请求的一张卡；
5. 输出优先满足前端旧字段；
6. 可以附加 `role`，但不要只输出自然语言长文；
7. 不做复杂清洗，不依赖代码节点兜底；
8. 不输出 `<think>`、推理过程、Markdown 包裹。

## 10. 验收矩阵

| ID | 场景 | 输入 | 期望 |
|---|---|---|---|
| A01 | 旧逻辑兼容 | 不传 P8 字段，传旧 `cardSequence` | 仍按旧序列生成，测试不退化 |
| A02 | 倒计时救命型 | `contentStrategy=countdown_rescue` | 生成封面、考试事实、计划、优先级、资料、技巧、CTA |
| A03 | 资料清单型 | `contentStrategy=resource_pack` | 至少一张资料清单卡，清单无 undefined |
| A04 | 钩子透传 | `hookPattern=if_start_today` | Dify payload 和生成结果体现“从今天开始备考”方向 |
| A05 | 人群适配 | `targetAudience=宝妈备考` | 标题/副标题/建议体现碎片时间或带娃场景 |
| A06 | 字段漂移兜底 | Dify 返回字符串 items 或非标准 days | 后端归一化后前端可渲染 |
| A07 | 单卡失败 | 某一张 Dify 空返回 | 重试，最终失败时落库且错误安全 |
| A08 | 前端展示 | 生成 6-8 张卡 | 无 `undefined`，非封面不显示大标题 |
| A09 | 安全边界 | 生成引用包含 internal/restricted | 权限仍按现有 ACL，不越权展示 |
| A10 | 真实烟测 | 执业药师 + 药学专业知识（一） | 能产出小红书风格内容，并通过人工快速验收 |

## 13. 停止点

出现以下情况必须停止，不要继续扩大改动：

- 旧生成链路被破坏；
- 真实 Dify 无法稳定返回单卡；
- 前端出现最大更新深度或渲染循环；
- 生成结果再次出现大量 `undefined`；
- Dify prompt 需要复杂代码节点才能跑通；
- 为了 P8 需要改数据库 schema。

## 14. 交付定义

P8 完成的定义：

1. 前端可选至少 5 个策略、6 个钩子；

7. P8 自测报告完成；
